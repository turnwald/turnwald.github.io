## Research question

Can an uncertainty-aware learned monitor detect manipulation failures more effectively than rule-based and uncertainty-free learned monitors while controlling false alarms and generalizing to held-out disturbances?

## Minimum scope

Use a simple, self-contained MuJoCo task such as grasp-and-lift or placement and generate reproducible runs with a small set of failures. Compare three variants: rule-based monitoring, learned monitoring without uncertainty estimation, and uncertainty-aware learned monitoring. Use simulation ground truth to label failure events and evaluate results; runtime monitors receive only explicitly documented, realistically observable signals, never privileged ground-truth labels or states used solely for evaluation. Separate training and evaluation by disturbance conditions. No reinforcement learning, hardware, ROS 2, project-specific components, complex manipulation development or outputs from other projects are required.

## Evaluation

The minimum study evaluates **failure detection after a defined failure onset**, not early prediction. For all three variants report event detection rate, missed failures, false alarms per run or unit time, and delay from ground-truth onset to first alarm, including results on held-out conditions. Assess uncertainty calibration and whether uncertainty identifies unfamiliar conditions. Document the label and onset definitions, monitor inputs and simulation limits; failure to outperform the baseline is a valid result.

## Prerequisites

Python, machine learning, experimental evaluation and willingness to learn basic robot simulation. ROS 2 experience is not required.

## Expected deliverables

Simulation and dataset-generation scripts; all three monitor variants; evaluation scripts, plots and thesis report. Provide a documented, implementation-independent interface specification defining timestamped observable inputs and score, optional uncertainty and alarm outputs, their units or meanings and timing. The specification is mandatory; ROS 2 implementation is not.

## First Iteration

**Objective:** Demonstrate failure monitoring from observable signals in a small simulated example.

**Task:**

Create a small simulation-only failure-monitoring prototype. A simple MuJoCo scene or recorded synthetic signal is sufficient for the initial exercise; a trained model is not required yet.

- Produce a nominal and a deliberately failed or disturbed run, and define how each is labelled.
- Implement a simple threshold-based alarm on an observable signal and show its output over time.
- Report whether the alarm detected the example failure and whether it raised a false alarm in the nominal run.
- Explain which signals would be available to a real robot and how a learned monitor and an uncertainty estimate could be evaluated later.
- Provide the script, run command and a plot or short log.

**Deliverables:** Provide the script and run command, a plot or short log of nominal and failed runs, and a brief description of observable signals and labels.

**Evaluation criteria:** Assess reproducibility, separation of observable inputs from evaluation labels, reported detection and false-alarm outcomes, and stated limitations.
