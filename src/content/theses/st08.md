## Research question

How does a traversability-aware costmap affect navigation success and terrain-risk exposure compared with obstacle-only planning in rescue-like scenarios?

## Minimum scope

Use a self-contained ROS 2/Gazebo simulation with defined terrain classes, a terrain-feature or traversability estimator and a costmap or planner layer. Compare it with an obstacle-only baseline in reproducible scenarios. Existing lab code and work from other projects are not prerequisites.

## Evaluation

Measure task success, terrain-risk exposure, path length, stuck/failure cases and computation time across the same seeded cases. Record assumptions about terrain labels and sensing.

## Prerequisites

ROS 2, Gazebo, Linux, Python or C++, navigation and mapping basics.

## Expected deliverables

Scenarios, costmap/planner interface, baseline and estimator, launch files, logs, evaluation scripts and thesis report.

## First Iteration

**Objective:** Compare navigation choices with and without terrain costs.

**Task:**

Create a minimal traversability-costmap prototype.

Use a simple 2D grid map with at least three terrain or risk classes, for example free space, obstacle, rough terrain, and high-risk terrain. Implement a planner that uses this costmap to find a path from start to goal. Compare the result against a planner that only avoids hard obstacles.

The first iteration should show:
- a traversability costmap,
- a planned path using only obstacle avoidance,
- a planned path using traversability costs,
- a short explanation of how the costmap could later be connected to a ROS 2 navigation stack.

**Deliverables:** Provide the runnable code, the costmap and both paths, and a brief comparison of their route lengths and terrain costs.

**Evaluation criteria:** Assess whether both planners use the same map, start and goal, whether costs are computed consistently, and whether the trade-off is explained.
