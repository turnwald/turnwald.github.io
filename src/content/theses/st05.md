## Research question

How can representative simulated servicing motion be mapped reproducibly to a lab-robot command interface, and what timing and tracking limitations does the mapping introduce?

## Minimum scope

Use a self-contained Basilisk chaser/target or servicing scenario, export representative relative poses or trajectories, and implement a documented mapping to a UR-compatible command representation with mock or simulated replay. Compare command and replay behavior under specified timing or trajectory variations. This remains a simulation-to-lab hardware bridge; a real robot is not required.

## Evaluation

Measure mapping error, simulated tracking error, command smoothness and timing; document scaling, frames, limitations and what replay cannot validate about orbital dynamics.

## Prerequisites

Python, simulation and robotics/control basics; ROS or UR experience is helpful.

## Expected deliverables

Scenario, command mapping and mock replay, reproducible tests and logs, interface documentation and thesis report.

## First Iteration

**Objective:** Demonstrate a testable data interface from simulated relative motion to a robot-side command.

**Task:**

Create a minimal software bridge concept between a simulated relative-motion or docking scenario and a laboratory robot motion command.

The first iteration does not need to control real hardware. It should demonstrate the data flow using a mock interface: a simulated chaser/target state or relative pose is converted into a simple robot-side command, such as a desired Cartesian pose, waypoint, or motion primitive for a UR-style manipulator.

The first iteration should show:
- a minimal simulation or scripted relative-motion example,
- a clear data interface between simulation state and robot command,
- a mock execution or printed command sequence,
- a short explanation of what would be required to connect this to a real UR robot safely.

**Deliverables:** Provide the script or minimal example, the mock command sequence, and a short description of the interface and safety considerations.

**Evaluation criteria:** Assess whether the data flow, coordinate conventions and command meaning are clear, and whether the example can be reproduced without hardware.
