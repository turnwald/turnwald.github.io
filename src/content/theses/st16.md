## Research question

How can a rover simulation be packaged and scored so new participants can reproducibly start and complete a defined challenge?

## Minimum scope

Package existing lunar rover assets with setup and launch instructions, at least one challenge, participant input/output interfaces, automated scoring and a minimal manual or teleoperation baseline. Do not provide a solution controller.

## Evaluation

Test installation and a complete challenge on a clean machine or container-like environment; document reproducibility, setup failures, scoring correctness and participant usability.

## Prerequisites

ROS 2/Gazebo, Python scripting, documentation and basic robotics.

## Expected deliverables

Launchable package, task and scoring specifications, test evidence, documentation and thesis report or agreed technical documentation.

## First Iteration

**Objective:** Illustrate how a small challenge can be presented and scored reproducibly.

**Task:**

Create a minimal prototype of a “setup-and-start” student challenge interface.

The first iteration does not need to implement a full rover simulation. It should define one small challenge, a start command or script concept, the expected student interaction, and a scoring output. The focus is usability for school or student groups.

The first iteration should show:
- one clearly defined challenge, for example waypoint navigation, sample return, obstacle avoidance, or mapping,
- a proposed folder or launch structure,
- a simple scoring rule,
- a mock run or example output showing how participants would know whether they succeeded.

**Deliverables:** Provide a concise challenge description, a proposed launch or folder structure, a scoring rule and a mock run or example output.

**Evaluation criteria:** Assess clarity of participant instructions, whether the scoring rule gives an unambiguous outcome, and whether the example demonstrates success or failure.
